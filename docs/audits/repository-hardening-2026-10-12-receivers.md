## Measured work and ratchets

The same `node scripts/bench-receipts.mjs` fixture was run against a temporary archive of the starting commit and the corrected checkout, using the same local dependencies and Node runtime. Twelve identical HTTP deliveries produced **12 classifications before, 1 after**, with twelve successful acknowledgments in both. This particular baseline sample had one persisted item because deliveries landed in the same second; that count is not a general baseline guarantee. See [before](artifacts/2026-10-12-final/receipts-before.json) and [after](artifacts/2026-10-12-final/receipts-after.json). No wall-time, memory, or token percentage improvement is claimed. The regression suite ratchets one classification per receipt and preserves operator edits.

The shared receiver path removes three copies of normalize/save/classify/log sequencing. Receipt lookup uses its authoritative record directly; there is no unbounded in-memory dedupe cache or historical-record scan. Requests retain existing 1 MiB input limits, authentication/signature checks, store locking, request-error handling, and local binding. Duplicate receipts still write the exact existing item/index to finish interrupted index updates, and emit a compact duplicate log; they do not discard observability. Failed normalization/classification can leave raw evidence but no accepted item, and retries reuse the same raw path.

## Contract review and boundaries

- New receiver IDs are opaque `itm_`-prefixed full hashes; metadata gains `receipt_hash`. No repository consumer parses the old timestamp-based ID layout. Existing stored IDs and direct normalizer outputs remain supported. There is no migration of old receipts: first redelivery of a pre-upgrade receipt can create a new tracked item. Deleting the item ends its dedupe lifetime. Changes to JSON delivery metadata count as changed payloads. These boundaries are documented in [source adapters](../source-adapters.md).
- Public normalizer functions accept an optional fourth argument; old three-argument calls remain valid. HTTP routes, statuses/shapes, authentication, CLI flags, exit codes, environment variables, archive format and source configuration are unchanged. Markdown exports intentionally add a section, documented in [Strata integration](../strata-integration.md).
- Persistence review covered source writeback, item/index order, receiver interruptions, locks and retry state. Existing restore journal, alias, action reconciliation, attachment containment, resource reader and bounded-ingestion regressions remain part of the full suite. No power-loss/fsync or hostile-filesystem transaction guarantee is added.
- Reviewed failure boundaries include failed classification, post-commit retry, unreadable/disappearing backups, export bookkeeping, adapter body limits and signatures. The audit does not claim a plugin-managed security scan or live provider delivery certification.
- Agent-facing context remains concise CLI/JSON results plus on-disk evidence. No prompt/schema change or token reduction claim was justified. Dependency/lockfile changes, broad module rewrites and unrelated cosmetic cleanup were not warranted.
- No unresolved P0–P2 finding or cross-repository requirement was introduced. Needs more evidence: existing live provider/deployment, network-filesystem and power-loss boundaries. Not worth changing: established direct-normalizer and source configuration contracts solely for style.
